# АВЛИ

Система учёта дополнена публичным сайтом на Next.js и Telegram-ботом. Существующие кабинет жильца, квитанции, отчёты и Django-админка сохранены.

## Запуск через Docker

1. Скопируйте пример окружения:

   ```powershell
   Copy-Item backend/.env.example .env
   ```

2. Заполните в `.env` как минимум `SECRET_KEY`, `DATABASE_PASSWORD`, `BOT_TOKEN`, `TELEGRAM_BOT_USERNAME` и `INTERNAL_API_TOKEN`.

3. Соберите и запустите сервисы:

   ```powershell
   docker compose up --build -d
   ```

   Для проверки конфигурации без локального `.env` можно использовать пример:

   ```powershell
   $env:AVLI_ENV_FILE='backend/.env.example'
   docker compose --env-file backend/.env.example config
   ```

4. Откройте `http://localhost`. Админка находится на `http://localhost/admin/`, а существующий поиск по лицевому счёту — на `http://localhost/account/`.

Первого администратора можно создать командой:

```powershell
docker compose exec django python manage.py createsuperuser
```

## Состав

- `frontend` — публичный сайт на Next.js 16: главная, компания, услуги, контакты и SEO-маршруты;
- `django` — существующая админка, печать квитанций, кабинет жильца, API контента и заявок;
- `bot` — Telegram polling-бот на aiogram;
- `db` — PostgreSQL 16;
- `nginx` — reverse proxy, статика, media и ограничение частоты запросов к API.

Публичный поиск принимает только точный лицевой счёт, ответы не кешируются. JSON API защищается заголовком `X-AVLI-API-Key`, когда задан `INTERNAL_API_TOKEN`.

## Контент публичного сайта

Публичный контент редактируется в Django-админке без изменения кода:

- «Настройки сайта» — контакты, тексты о компании, карта и главные SEO-поля;
- «Слайды», «Преимущества», «Показатели», «Отзывы» и «Частые вопросы»;
- «Услуги» — описание, изображение, категория, порядок, публикация и отдельные SEO-поля;
- «Заявки с сайта» — обращения из формы обратного звонка со статусами обработки.

Next.js обновляет опубликованные данные автоматически с интервалом до пяти минут. В проекте настроены канонические адреса, Open Graph, структурированные данные Schema.org, `sitemap.xml`, `robots.txt` и постоянные редиректы со старых URL `avli.kg`.

Для основного домена задайте в `.env`:

```dotenv
ALLOWED_HOSTS=avli.kg,www.avli.kg
CSRF_TRUSTED_ORIGINS=https://avli.kg,https://www.avli.kg
NEXT_PUBLIC_SITE_URL=https://avli.kg
```

После изменения `NEXT_PUBLIC_SITE_URL` пересоберите frontend, потому что адрес используется в статических SEO-метаданных:

```powershell
docker compose up --build -d frontend nginx
```

## Архив начислений и своды

Расчёты каждого абонента за закрытый месяц складываются в раздел **Архив начислений**
(`PeriodSnapshot`): по строке на абонента за каждый месяц, с копией ФИО, адреса, площади
и тарифа. Снимок снимается в момент закрытия периода — до того, как графы абонента
перепишутся под новый месяц, — поэтому архив показывает ровно то, что было напечатано
в квитанции.

Порядок месячных операций (памятка есть и в самой админке):

1. в течение месяца — загрузка банковских реестров в разделе «Платежи»;
2. в начале следующего месяца — печать квитанций;
3. действие «Начислить за новый месяц»: в нём **явно выбирается закрываемый месяц**,
   по нему пишется архив, остатки переносятся на начало нового периода и начисляется
   тариф. Если архив за этот месяц уже есть, действие останавливается — это защита от
   повторного начисления;
4. отчётность — страница **Свод за месяц** (`/reports/monthly`, только для персонала).

Свод строится агрегацией архива и открывается в двух режимах:

- **по домам** — строка на дом плюс «ИТОГО» по всем домам: форма для бухгалтерии;
- **по абонентам** — расшифровка внутри одного дома, с флажком «только должники»:
  то, что бухгалтер отправляет домкому.

Обе формы печатаются из браузера, скачиваются в PDF (A4 альбомный) и в Excel.
Графы «3%», «Перевод», «Пеня» и «Возврат» — справочные: они хранятся в архиве,
печатаются в своде и правятся вручную, но на сальдо абонента не влияют. «3%» при записи
в архив проставляется как доля от начисленного и оплаченного по КУ.
Просроченная задолженность считается по каждому абоненту как
`max(0, долг на конец месяца − начислено за этот месяц)`.

## Дома и адреса

Адрес абонента разложен на справочник домов (`House`) и номер квартиры; поле «Адрес»
собирается из них автоматически и используется в квитанциях. Благодаря этому в админке
работают фильтры по улице и по дому, а свод группируется точно.

Существующие адреса разобрала миграция `0005_fill_houses_from_address`. Для абонентов,
загруженных позже из DBF или другого внешнего источника, есть команда:

```powershell
docker compose exec django python manage.py sync_houses            # только без дома
docker compose exec django python manage.py sync_houses --dry-run  # проверить разбор
```

Правила разбора и список написаний одной и той же улицы лежат в
`backend/users_app/addresses.py` — их можно дополнять. Сам справочник домов
редактируется в админке: переименование дома сразу подтягивается в адреса абонентов.

## Локальные тесты без PostgreSQL

```powershell
$env:USE_SQLITE='True'
$env:DEBUG='True'
python backend/manage.py test users_app
```

Для production подключите HTTPS на внешнем reverse proxy или добавьте сертификат в nginx, затем выставьте `SECURE_SSL_REDIRECT=True`, `SECURE_COOKIES=True`, укажите HTTPS-домен в `CSRF_TRUSTED_ORIGINS` и только после проверки HTTPS настройте `SECURE_HSTS_SECONDS`.
